# A CH32V006K8U6 module

A small module around WCH's **CH32V006K8U6** (QFN32, 62 KB flash, 8 KB
SRAM, the QingKe V2C core), the RISC-V board of the bench. Documents of
record: the CH32V006 datasheet V2.0 and the CH32V00X reference manual
V1.5 (WCH's site; the local copies are in the desk's document
folder). Silicon identity: ChipID `0x00600620`, `misa` `0x40801014`
(E, C, the multiply-only M, and WCH's own extension), `marchid`
`0xdc68d843`.

- **Clock**: HSI 24 MHz; the chip wakes at HSI/3 = 8 MHz (HPRE's reset
  value) and the kernel apps run the PLL at 48 MHz. No crystal fitted.
- **Supply**: 3.3 V, taken from the probe's 3V3 pin.
- **Debug**: PD1 = SWDIO (1-wire SDI, the default), PB3 = SWCLK (the
  2-wire mode), GND - [../probes/wch-link.md](../probes/wch-link.md).
  The QFN32 pin numbers, for a board with no silkscreen: PD1 is pin
  23, PB3 pin 1, PD5 pin 27, PD6 pin 28.
- **Console**: USART1 on PD5 (TX) / PD6 (RX), the default alternate
  function, wired to the WCH-Link's TX/RX - so the probe's own serial
  port is the console, at 115200. The same two pins are WCH's serial
  ISP path, the way back in should a program ever close the debug
  interface.
- **LED**: the module's LED has no pin of its own - it is jumpered, and
  every app of the project drives **PC0** (pin 13): bonded on all five
  packages of the family, no bus and no analog function, TIM2_CH3 as
  its alternate function.
- **What it shipped with**: WCH's EVT demo, which prints
  `SystemClk:48000000` and `ChipID:00600620` on USART1 at reset; saved
  as a 62 KB image (4144 bytes used) before the first flash, in the
  desk's document folder.
- **Option bytes** as found: `0x08f75aa5` - RDPR `0xA5`, the flash
  unprotected; USER `0xF7`; FLASH_WPR all ones, no unit protected.
- **Storage**: the image gets 40 KB, the top 22 KB are the NvHeap's and
  the NvJournal's ([../ch32v00x/nvm.md](../ch32v00x/nvm.md)); `test_ch32_nvm`
  letter `w` wipes them.
- **Reset pin**: PA7 on this package (DS 2.1's note), so PC5 and PD7
  are ordinary pads here.
- **The jumpers the suites want**, each probed by its suite and each
  letter declining without it: PD2 to PD4 (pin 24 to pin 26) serves
  `test_ch32_tim`'s captures and `test_ch32_pin`'s levels, edges and
  scanner; PC6 to PC7 (pin 20 to pin 21) is `test_ch32_spi`'s loopback;
  `test_ch32_i2c` wants a peer board running `twi_peer` on PC2 (SCL,
  pin 15) and PC1 (SDA, pin 14) with the peer's pull-ups and a shared
  GND - this module has none. PC4 (pin 18) carries the remap and ADC
  letters through its own pull, no wire; the LED is on PC0 (pin 13).
- Manifest type `v006k8`; the project is `ch32v00x/`
  ([../ch32v00x/README.md](../ch32v00x/README.md)).
